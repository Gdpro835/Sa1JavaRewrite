# Delta-time / GLES migration

## Статус и границы результата

Реализовано новое ядро, подключён настоящий GLES-рендерер и изменена значительная часть игрового кода. Выбран именно **variable-delta update**, а не прежняя симуляция с фиксированным шагом и интерполяцией картинки. Формат Sketchware сохранён.

**Это ещё не завершённая и проверенная перепись всей игры.** Перенос большого объёма декомпилированного кода требует дальнейшего семантического аудита и Android-проверок. Нельзя выводить готовность всех игровых сценариев из успешной компиляции. Ни APK, ни скриншоты с устройства, ни измерения производительности GPU в этом окружении не получены.

## 1. Время и единицы

`FrameClock.advance(nowNanos)` возвращает реальное прошедшее время в секундах. Первый кадр после создания/сброса имеет delta 0. Длинный интервал ограничивается **100 мс**, отброшенное время доступно через `getDroppedSeconds()`.

Это защитная политика: после длительного зависания игра не пытается мгновенно проиграть всё пропущенное время. При длительных интервалах больше 100 мс симуляция замедляется относительно настенных часов. Это не fixed-step catch-up. Ограничение delta сверху не задерживает и не пропускает короткие кадры.

`FRAME_SKIP` и старые методы задания периода кадра удалены. `GLSurfaceView` работает в `RENDERMODE_CONTINUOUSLY`: искусственного ограничения на 15 FPS нет; фактический FPS зависит от VSync/частоты дисплея и нагрузки. Отдельная константа длительности интро в `MainState` тоже удалена — интро использует стандартные длительности `AnimationDrawer` без изменения скорости.

Один вызов `MFDevice.renderFrame`:

1. Вычисляет эффективный delta с учётом паузы/браузера и bullet time (`1/16`).
2. Вызывает `GameTime.beginFrame`.
3. Обрабатывает ввод и делает не более одного `onUpdate(delta)`.
4. Рисует pre-layer, логическую игровую сцену и post-layer непосредственно через GPU.

Координаты мира остаются целочисленными, обычно **1/64 пикселя**. Число `0.063` сохранено только как **единица пересчёта авторских констант и длительностей ассетов**:

```
authored velocity / 0.063 = world units per second
elapsed authored units = deltaSeconds / 0.063
```

Оно больше не задаёт период выполнения игрового цикла. Поля со старыми именами `frame`, `count` и `*_cnt` часто являются представлением прошедшего времени в этих единицах, но номер состояния, количество атак/колец и индекс массива сами по себе временем не являются.

### Накопители

`GameTime` хранит состояние по паре **владелец + имя канала**, со слабыми ссылками на владельцев. Значения между целыми координатами/счётчиками не теряются. Разные объекты и элементы массивов не должны использовать общий канал.

```java
// Непрерывное ускорение и движение.
velY = GameTime.advance(this, "velY", velY, gravity);
posY = GameTime.advancePosition(this, "posY", posY, "velY", velY);

// Уже вычисленная геометрическая поправка: БЕЗ дополнительного deltaTime.
worldCal.actionLogic(destinationX - oldX, destinationY - oldY);

// Мгновенный импульс.
velY = -jumpSpeed;

// Явный новый отсчёт, даже если целая часть уже равна нулю.
waitCount = GameTime.set(this, "waitCount", 0);

// Один общий таймер на кадр, а не по одному инкременту на каждого игрока.
powerup = GameTime.advanceOnce(PlayerObject.class, "powerup", powerup, -1);
```

`advancePosition`/`integratedVelocity` используют среднюю скорость за интервал, если ускорение отслеживается тем же владельцем/каналом и скорость не была перезаписана импульсом. Для постоянного ускорения это устраняет обычную зависимость траектории от порядка Euler-update. Это **не доказательство** точной интеграции всех нелинейных сил и контактов игры.

Для вычисленной из перемещения скорости, например при выходе с рельса, используется `velocityFromDisplacement`. Иначе перемещение за один короткий кадр ошибочно становится скоростью на целую авторскую единицу.

## 2. События, циклы и сглаживание

- `crosses` — **непотребляющий предикат уровня**: точное значение либо пересечённый в этом кадре порог.
- `event` — latch полного условия для одноразового действия. Все условия готовности должны быть внутри него; нельзя потребить событие до проверки направления, ввода или доступности объекта.
- Для постоянной готовности используется обычное `timer >= limit`, а не latch. Мигание также остаётся предикатом фазы, а не однокадровым событием.
- `periods` возвращает число пересечённых периодических границ. `periodic` подходит, когда несколько событий допустимо объединить в одно, например звук. Для количества частиц/выплат используйте число, а не boolean.
- `wrap` сохраняет дробную часть и историю перехода через границу. Учтены и периоды, не делящие длину цикла, и обратные счётчики.
- `steps` перечисляет пересечённые целые значения для **событийного** switch-таймлайна. Это не шаги физики; защитный лимит — 4096 событий за вызов.

После переноса нельзя оставлять `timer = GameTime.set(..., timer % period)` на каждом кадре: это уничтожает дробную часть. Нельзя также второй раз умножать дискретный инкремент на delta внутри уже сработавшего периодического события.

`MyAPI.calNextPosition` и `calNextPositionReverse` теперь требуют владельца/канал. Все их существующие игровые вызовы обновлены. Целочисленный результат без сохранения остатка останавливался бы в нескольких пикселях от цели при высоком FPS. Математика этих контроллеров вынесена в тестируемый `GameTime`; double/float-варианты не округляют промежуточное значение.

## 3. Рендерер

Новые файлы находятся в `com/sega/mobile/framework/opengl`:

- `SpriteBatch` — GLES 2 shaders, треугольники/квады, батчи, кэш текстур по bitmap identity и generation ID, scissor и статистика.
- `GLGraphics` — совместимый с существующими вызовами `Graphics` фасад: матрицы, anchors, регионы, текст, примитивы и эффекты.
- `SpriteTransform` — все восемь преобразований MIDP без Android-зависимостей.

Полноэкранный `Bitmap` с CPU-отрисовкой не загружается в GL на каждом кадре. Обычные спрайты хранятся в текстурах и рисуются геометрией. Эффекты `MFGraphics` и затемнение экрана используют GPU-путь, а не попиксельную обработку всего кадра.

Смешивание: **`ONE, ONE_MINUS_SRC_ALPHA`**, поскольку Android-битмапы premultiplied. При потере EGL-контекста GL-имена сбрасываются, нужные текстуры повторно загружаются из CPU-ассетов. Изменение mutable bitmap определяется по generation ID.

Старая программная обёртка `Graphics` остаётся для подготовки offscreen-ассетов. Растеризация строк выполняется при заполнении кэша текста (до 128 записей / 8 MiB), с учётом масштаба итоговой матрицы; сглаживание системного текста независимо от пиксельных спрайтов. Legacy `drawRGB` по необходимости создаёт небольшую текстуру; это не общий способ рисования сцены.

### Ограничения GPU-пути

- Runtime-компиляция GLSL, корректность EGL-конфигурации и картинка на Android-драйверах **ещё не проверены**.
- Scissor прямоугольный; для clip после произвольного поворота используется охватывающий прямоугольник, не stencil-маска.
- Антиалиасинг примитивов не эквивалентен Android Canvas. Нужно сравнить дуги, тонкие линии, края атласов и масштабирование.
- Бюджет кэша текстур — 48 MiB, **мягкий**: текстуры текущего кадра не вытесняются посреди этого кадра.
- `GL_MAX_TEXTURE_SIZE` должен быть не меньше размера крупнейшего используемого изображения. Для текущих PNG-ассетов нужен минимум 2048; текст и динамические изображения тоже не должны превышать лимит устройства.
- API статистики: `Canvas.getRendererStats()` → `getDrawCalls()`, `getTextureCount()`, `getTextureBytes()`. Чтение предназначено для GL-потока.

## 4. Android / Sketchware

Сохраняются `data/602`, `mysc/list/602/project`, `resources`, `libs` и существующая схема manifest injection. Ни Gradle, ни SDK/JAR/APK-бинарники в репозиторий не добавлены.

`project_config.min_sdk = 14`: необходимы GLES 2 APIs, управление EGL-контекстом и `Bitmap.getGenerationId()`. Во время запуска проверяется заявленная устройством поддержка GLES 2.0. Поднятие минимального SDK не означает, что весь старый Android-код протестирован на каждой версии от 14.

Для распространения APK рекомендуется декларация в **корне** сгенерированного manifest:

```xml
<uses-feature
    android:glEsVersion="0x00020000"
    android:required="true" />
```

В сохранённой схеме `app_components.txt` вставляется внутрь `<application>`, а `_application_permissions` создаёт `<uses-permission>`. Они **не подходят** для этой декларации. Поэтому некорректная feature-вставка в эти файлы не добавлена. Если ваша версия Sketchware имеет редактор корня manifest, добавьте feature там; иначе используется runtime-проверка. `targetSdk 25` оставлен как был — требования современных магазинов и адаптация под новый targetSdk не входят в эту миграцию.

Окно создаёт новый `GLSurfaceView` на каждой Activity. Состояние не удерживает старый Activity через `MainState`. Ввод передаётся в очередь GL-потока, указатели сбрасываются при потере фокуса/паузе/cancel; контекст и текстуры могут восстанавливаться независимо от игрового состояния. Финальное закрытие выполняется под блокировкой после остановки GL-worker и до очистки ссылки на Activity, чтобы не ставить сохранение/освобождение ресурсов в очередь уже отсоединённого view. UI-адаптеры перепривязываются к новому Activity без повторной загрузки игровых записей.

Старый сетевой прототип **не переписан в полноценный протокол**: сериализация игровых объектов, авторитет состояния, переподключение, безопасность десериализации и синхронизация разных частот кадров остаются отдельными проблемами. Перенос применения полученных полей в игровой поток не делает multiplayer готовым. Звуковой backend также не заменялся целиком.

### Исправление регрессий вступления и Character Select (2026-09-21)

Перед исправлением выполнен `git pull --ff-only`, получен `9ced40e`; пользовательская правка `hardwareAccelerated` сохранена.

Character Select ожидал `checkEnd()` у зацикленной рамки. Старый draw успевал выставить флаг окончания **до** включения loop; после переноса анимации в update этот побочный эффект исчез. Сценарный тест воспроизвёл зависание после первого переключения. Теперь завершение перехода отслеживается по конечной анимации поворота в `characterSelectLogic`, а не в draw; loop задаётся однократно. `restart()` снова ждёт draw/`moveOn`, чтобы переиспользованные, пока скрытые элементы не проигрывали вход заранее.

В заставках визуальный прогресс берётся из дробного времени, а не целого старого счётчика. Растяжение строки логотипа выполняется одним квадом вместо множества строк. Затемнение имеет прямой GPU-путь. Из освобождения интро/титула удалены ручной GC и два ожидания по 100 мс.

Для интро и элементов выбора включён `AnimationDrawer.setInterpolateMotion(true)`: координаты совместимых слоёв ассета плавно переходят к следующей позе, включая вложенные Qi-кадры. Это **не** fixed-step симуляция и не ускорение проигрывания: длительности, смена sprite-cell и игровая физика не меняются. Длинные удержания остаются неподвижными до последней авторской единицы; неоднозначные повторяющиеся слои и большие скачки не смешиваются. По умолчанию эта опция выключена и для ненулевого внешнего трансформа используется прежнее дискретное рисование.

### Исправление остальных меню (2026-09-21)

Перед работой выполнен `git pull --ff-only` текущей ветки; удалённая версия совпадала с `ec3b31c`. Изменения манифеста не затрагивались.

В сценарных тестах воспроизведены три регрессии: синяя полоса начиналась с X=99 вместо левого края; при завершении строки позиция настроек прыгала с −22 на −12 при 30 FPS; превью управления повторно читало ресурсы в каждом draw.

- **Настройки:** нормализованный остаток `GameTime.wrap` учитывается при тайлинге синей полосы. Добавлены крайние тайлы и дробное графическое смещение — полоса не теряет левый/правый край при переходе через период. Её время обновляется в logic.
- **Прокрутка:** общий `MenuScroll` хранит одну дробную координату для настроек/уровней. Геометрическое смещение строки больше не умножается на deltaTime повторно. Перетаскивание использует абсолютное перемещение указателя; инерция уровней — скорость в секунду с аналитическим торможением. Сохранены шаг 24 px, ограничение краями и возврат после перетаскивания за границу. Отпускание после drag не активирует пункт.
- **Главное меню:** исправлено несовпадение шага (18 в логике против 20 в рисунке); сглаживание перенесено в update. Дробные координаты списков и главного меню передаются рендереру, а не отбрасываются перед масштабированием. Существующий целочисленный `translateCanvas` не изменён — добавлен float-overload для UI.
- **Выбор уровня:** музыка запускается один раз при входе; входящие строки ограничиваются фактической интегрированной позицией, а не сырым значением скорости. Центры областей нажатия совпадают с надписями. Ограничение рисования списка снимается перед заголовком/стрелками/возвратом.
- **Превью управления:** изменение размера обновляет нужный ассет; размер/положение обновляют области кнопок. Обычное рисование больше не перечитывает JSON/PNG и не пересоздаёт ввод каждый кадр. Прозрачность не требует перезагрузки спрайтов.
- **Справка/титры и модальные окна:** фон обновляется по времени в logic, не по числу рисований. Общий fade продвигается не более одного раза за update; явный перезапуск сбрасывает дробный остаток.

`tools/test_ui.sh` запускает обе UI-серии и игровую серию. Для отдельной серии можно задать `UI_TEST_CLASS=OtherMenuRegressionTests`; необязательный аргумент — `band`, `scroll`, `stage`, `main`, `gestures`, `preview`, `pages` или `backgrounds`.

Проверены интервалы 10–144 FPS и нерегулярный deltaTime для чистого контроллера; сценарии списка — 30/60/120/144 FPS. Графические проверки используют команды, области и факт передачи дробной трансформации, **не** пиксели Android/GLES. На устройстве ещё нужно проверить швы/фильтрацию синей полосы, все размеры логического экрана, реальные мультитач/отмену жеста, читаемость шрифтов и frametime. Это исправление воспроизведённых проблем, не утверждение, что все экраны и драйверы уже проверены.

### Пауза, кольца и завершение обычных уровней (2026-09-21)

Исправлены ошибки, обнаруженные после проверки тестером:

- Пауза мира задаётся **до** трёх animation-registry update, а lifecycle `pauseCheck()` выполняется первым. `GameState` сообщает о паузе/interrupt; `GameObject.logicObjects` и мировой проход рисования помечают относящиеся к миру анимации. Мир и UI не делят один переключатель паузы: меню продолжает работать. Scope восстанавливается через `finally`; на interrupt временно останавливаются и старые render-side счётчики, использующие `GameObject.IsGamePause`.
- В `AnimationDrawer` сохранён старый контракт: `setPause(true)` выключает **автоматическое** проигрывание, но `moveOn()` явно продвигает анимацию. Так работают общие кольца, факелы и ряд эффектов. Пропущенный автоматический update не расходует метку кадра; несколько draw/`moveOn` не ускоряют одну анимацию. Общая/мировая пауза по-прежнему блокирует явное продвижение.
- Завершение анимаций 35/37 фиксируется в `PlayerObject.logic()` до изменения позы контроллером. Проверяется, что завершился именно проигранный вариант финиша/празднования, а не старый drawer другой позы. `draw()` больше не вызывает `StageManager.setStagePass()`.
- Джингл запускается однократно при начале плашки результатов, вместо сравнения `offsetx == SCREEN_WIDTH - movespeedx`. Такое равенство пропускалось при дробном delta. Плашка ограничивается конечными координатами; повторное рисование не двигает её второй раз за update. Терминальные countdown-таймеры `StageManager` ограничены снизу нулём.

Новый headless-прогон загружает карты актов 1/2 первой зоны, настоящих игроков, коллизии, объекты, анимации и `GameState`. Для финиша используется объект знака из карты; для капсулы пропускается только бой с боссом — проверяются реальные кнопка, освобождение животных и последующая логика. Проверены Sonic/Tails/Knuckles/Amy, верхняя кнопка и удар молотом Amy, а также 10/30/60/120/144 FPS и нерегулярные интервалы. Проверяется не только флаг победы: должны быть отрисованы строки результатов, запрошен ровно один правильный трек (26/27) и достигнуто состояние перехода на следующий этап.

Пауза проверяется на реальном `GameState`, с дополнительными мировыми probes для `AnimationDrawer`, прямого `Animation.Action` и `PyxAnimation`. UI-probe продолжает играть, мировой clock и позы стоят; отдельно проверены interrupt, возврат и запрет завершать уровень из paused draw на границе анимации.

```bash
ANDROID_JAR=/path/to/android.jar JSON_JAR=/path/to/json-20240303.jar \
  UI_TEST_CLASS=SonicGBA.GameplayRegressionTests ./tools/test_ui.sh
```

Необязательные аргументы: `rings`, `bar`, `pause`, `goal`, `cage`, `countdowns`. В этой серии координаты игрока переносятся к финишу; это **не полное прохождение** уровней. Аудио-адаптер записывает запросы треков, но не воспроизводит их; графический адаптер записывает команды, но не проверяет пиксели GLES. Остальные зоны, спецэтап, multiplayer и реальные Android lifecycle/драйверы требуют отдельного прогона.

### Системный шрифт подсказок (2026-09-21)

В прежнем Canvas-пути `enableClearFont` рисовал системный текст в отдельном слое с экранным масштабом до растеризации. В GLES строка рисовалась в маленькую логическую текстуру (например, 11 px), причём общий `setAntiAlias(false)` отключал сглаживание и у текста. Последующее растяжение этого изображения вместе со сценой теряло детали букв.

`TextTextureCache` строит маску под масштаб итоговой матрицы, включая поворот/неравномерное масштабирование. Сглаживание текста независимо от настройки пиксельных спрайтов; сохраняются системная гарнитура, логический размер, базовая линия, anchors, цвет и обводка. Учтены отрицательный боковой вынос, акценты и нижние элементы букв. Растр/кэш различаются по разрешению; одинаковая строка переиспользуется всеми проходами обводки и заполнения.

Кэш ограничен 128 записями и 8 MiB; один растр — 1 мегапикселем и `GL_MAX_TEXTURE_SIZE`. Масштаб выбирается целыми уровнями до 16, а чрезмерно длинные/увеличенные строки переходят на меньший растр **до** выделения bitmap. Системные глифы не растеризуются заново каждый кадр; полного CPU-буфера экрана нет. Изображения `TIPS`/`LOADING` и тексты в ассетах не менялись.

```bash
./tools/test_text.sh
```

Тест выполняет настоящие `TextTextureCache` и `Font`, но заменяет Android Paint/Canvas/Bitmap детерминированными адаптерами. Он проверяет размеры, AA, baseline, выносы, кэш и лимиты, **не** внешний вид Android-глифов. Сравнение подсказок/справки на устройстве при нескольких масштабах и языках остаётся обязательным.

## 6. Что ещё нужно проверить и закончить

1. **Android smoke-test рендерера:** загрузка, меню, один уровень, shaders, цвет/alpha, flip/rotation, clip, native pre/post layers, текст, fade, потеря EGL.
2. **Полный аудит игрового содержимого:** остаточные неочевидные алиасы скоростей, draw-side effects, случайные действия на кадр, вычисляемые индексы и готовность атак. Часть старого `draw` всё ещё меняет визуальное/игровое состояние; это не полностью чистый render.
3. **Все персонажи:** Sonic, Tails, Knuckles, Amy, Super Sonic — разбег, отпускание прыжка, удары, полёт/планирование/лазание, вода, антигравитация, рельсы, трубы, смерть/респаун и компаньон.
4. **Все боссы и объекты:** атаки/фазы, повторные попытки, бочки/платформы/пружины/ловушки, переходы между зонами; отдельно Boss4 и длинные таймлайны BossF3.
5. **UI и финалы:** счёт, game over/continue, настройки, спецэтапы, результаты, все концовки, повторный вход в состояние.
6. **Lifecycle:** 20 циклов background/foreground, блокировка экрана, браузер и возврат, пересоздание Activity, cold restart; без ускоренного catch-up, чёрного экрана, двойного звука и зажатой кнопки.
7. **Производительность:** запись frametime/CPU/GPU/памяти на устройстве. Само наличие OpenGL не гарантирует 60/120 FPS — игровая логика, загрузка ресурсов и звук остаются нагрузкой CPU.

Для сравнения на устройстве используйте одинаковый сценарий ввода и измеряйте **секунды**, а не количество отрисовок. Проверяйте путь за заданное время, высоту/длительность прыжка, длительность power-up, число атак/звуков и момент перехода фазы. Из-за variable-step контактов и отсутствия детерминированного replay полное битовое совпадение состояний между устройствами не обещается.
